Customize with Sass

Budu is developed mobile-first with a modular Sass architecture. Customization happens via variables, maps, and mixins, so you can change colors, spacing, typography, and more without touching core files.

Variables

Every Sass variable in Budu includes the !default flag, meaning you can override them by assigning your own values before importing Budu. Here's a typical budu.scss:

// 1. Include functions, variables and mixins first (if importing individual parts)
@import "node_modules/budu/scss/functions";
@import "node_modules/budu/scss/variables";
@import "node_modules/budu/scss/maps";
@import "node_modules/budu/scss/mixins";
@import "node_modules/budu/scss/mixins/utility-api";

// 2. Here add your own overrides
$budu-primary: #7952b3;
$budu-danger: #e83e8c;
$budu-border-radius: 0.375rem;

// 3. Optionally include any of Budu's parts
@import "node_modules/budu/scss/root";
@import "node_modules/budu/scss/reboot";
@import "node_modules/budu/scss/grid";

Maps and loops

Budu uses Sass maps for its color system, spacers, breakpoints, and the utility API. Override a map to change many classes at once. For example, add a new theme color and every .bg-*, .text-*, and button variant is generated for you:

$budu-theme-colors: map.merge($budu-theme-colors, (
  "turquoise": #20c997,
));

Customizing components

Generated button variants, badge, alert, and other components will all pick up the new color automatically.

Pro tip: You only need to import the config layer (functions, variables, maps, mixins, utility-api) if you want to use Budu's mixins and maps in your own Sass, then import the partials you actually need for the leanest output.
