Why Migrate from Tailwind to boodoo?

  • No Build Tool Lock-In: Works instantly with vanilla HTML, PHP, Rails, or Next.js without PostCSS, npm watcher pipelines, or complex configuration files.
  • Clean Readable Markup: Replace 15 repetitive atomic classes on cards and buttons with semantic primitives like .card, .btn, and .badge.
  • Zero-Config JS Included: Built-in modals, tooltips, collapse, command palette, and drawer menus without needing Headless UI or external React dependencies.

Automated CLI Codemod

Transform repetitive Tailwind class chains into clean Boodoo utilities and component classes using the built-in CLI:

# Codemod files in ./src or an HTML template
npx boodoo migrate --from=tailwind ./src
npx boodoo migrate --from=tailwind index.html

Tested Compatibility & Known Limitations

Here is what the Tailwind codemod supports and the boundaries of automatic translation:

Utility / Pattern Status Behavior & Guidance
Flexbox & Alignment Supported flex flex-col, items-center, justify-between map cleanly to .flex-column, .align-items-center, .justify-content-between.
Spacing & Padding Supported Standard spacing scales (p-1 to p-5, m-1 to m-5, gap-1 to gap-5) map to Boodoo's proportional spacing tokens.
Grid Containers Supported grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 maps to row row-cols-1 row-cols-md-2 row-cols-lg-3.
Arbitrary Values (`[#123456]`, `top-[17px]`) Limitation Ad-hoc JIT bracket syntax (e.g., w-[347px]) cannot be guessed by static regex. Use scoped CSS custom properties or token variables (--boodoo-spacer-*).
Dynamic State Modifiers (`group-hover:*`, `peer-*`) Limitation Tailwind compound peer/group states require custom CSS rules or CSS :has() parent selectors supported natively in modern browsers.
